# Security policy

## Supported version

Security fixes are applied to the latest revision of the `main` branch.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use GitHub's private vulnerability reporting feature from the repository's **Security** tab and include:

- the affected component and revision;
- reproduction steps or a proof of concept;
- expected and observed impact;
- any suggested mitigation.

The maintainer will acknowledge a complete report as soon as practical, coordinate remediation, and credit reporters who want public acknowledgement.

Never include production credentials, personal data, or active access tokens in a report. Rotate any credential that may have been exposed.
